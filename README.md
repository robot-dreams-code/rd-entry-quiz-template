# r_d Вхідний квіз «Готовність до старту» — шаблон

Інтерактивна сторінка у стилі robot_dreams: студент, який уже купив курс, перед стартом відповідає на 12–15 питань і отримує результат — **готові / готові з підготовкою / радимо спершу закласти основи** — з розбором за темами і **матеріалами, де підтягнути кожну прогалину**.

Архітектура як у [FAQ-шаблону](https://github.com/robot-dreams-code/rd-faq-template.github.io): питання, тексти й матеріали живуть у Google-таблиці, сторінка — на GitHub Pages. Один шаблон — окремий репозиторій і окрема таблиця для кожного курсу.

Приклад у цьому репозиторії — курс «Розробка пристроїв акустичної детекції» (`data/`). Другий приклад — «Python для військових технологій» (`examples/python-miltech/`): щоб побачити його, скопіюйте ці файли в `data/`.

У репозиторії також:
- `skill/` — скіл `rd-entry-quiz` для корпоративного Claude (zip для завантаження і текст SKILL.md);
- `prompts/generator.md` — той самий набір правил як промпт, якщо скіла немає.

## Новий курс за 15 хвилин (+ пів години на контент)

1. **Контент.** Згенеруйте вміст таблиці скілом `rd-entry-quiz` у Claude (або [промптом](prompts/generator.md)) з програми й лендингу курсу і перевірте з лектором.
2. **Таблиця.** Створіть Google-таблицю: Файл → Імпорт → «Завантажити» → `table/rd-entry-quiz-table.xlsx` → «Замінити таблицю». Далі замініть приклад вмістом свого курсу. Назви вкладок (`settings`, `skills`, `questions`, `resources`, `courses`, `base`) не змінюйте.
3. **Доступ.** Налаштування доступу → «Усі, хто має посилання» → «Читач».
4. **Репозиторій.** На GitHub: «Use this template» → новий репозиторій (наприклад, `quiz-acoustic-detection-devices`).
5. **Конфіг.** У `config.js` вставте `sheetId` — частину адреси таблиці між `/d/` і `/edit`.
6. **Публікація.** Settings → Pages → Deploy from a branch → `main` / root.
7. **Резервна копія.** Actions → Sync quiz snapshot → Run workflow (далі запускається щогодини сам).

Після цього все редагується лише в таблиці. Зміни з'являються на сайті протягом кількох хвилин.

## Посилання і режими

| Посилання | Для чого |
|---|---|
| `…/` | **Основний сценарій.** Лист або LMS для студентів, які купили курс, за 1–2 тижні до старту. Без кнопок продажу; квіз для самоперевірки й самостійної підготовки: конспекти, матеріали й план кроків, без звернень до куратора |
| `…/?mode=landing` | Додатковий сценарій, якщо погодить маркетинг: лендинг або менеджери з продажу для тих, хто сумнівається. Тексти з ключів `*_landing`, кнопки «Детальніше про курс» і «Поговорити з консультантом», рекомендації курсів robot_dreams |
| `…/?embed=1` | Вбудувати в LMS або на лендинг в `<iframe>` — без шапки й футера |

Режими можна поєднувати: `?mode=landing&embed=1`.

## Вкладка `skills` — теми порогу входу

| id | name | description | critical | ok_text | gap_text | note | note_landing | stage | order |
|---|---|---|---|---|---|---|---|---|---|
| physics | Фізика звуку і хвиль | … | TRUE | Текст, коли на рівні | Текст, коли є прогалина | Що школа дає сама | Те саме для лендингу | Трохи фізики | 2 |

- **critical = TRUE** — лише для того, без чого старт неможливий. Тільки критична тема може дати результат «закласти основи». Некритичні прогалини завжди дають «готові з підготовкою».
- **recap** — короткий конспект теми: 4–6 рядків, кожен з нового рядка (Alt+Enter). Показується в картці прогалини блоком «Коротко про тему» — це головне, що допомагає закрити прогалину, тому формули й факти обов'язково перевіряє лектор. Markdown працює: `**жирний**`, `` `код` ``.
- **Загальні рекомендації.** Якщо рядки recap починаються з id теми в квадратних дужках — `[python] Python на рівні базових скриптів…` — такий конспект вважається загальним переліком для курсу. Квіз показує його окремим блоком «Загальні рекомендації» над розбором за темами (завжди, за будь-якого результату), у тій самій послідовності, що й картки тем нижче. Біля кожного пункту — позначка за відповідями студента («✓ у вас на рівні» / «варто підтягнути») і посилання «до теми ↓». У картці теми цей перелік не дублюється. Заголовок і підпис блоку можна змінити ключами `general_title` і `general_sub` у settings. Рядок без тегу теми — загальна порада без перевірки в квізі (наприклад, про англійську): він іде в кінці переліку з нейтральною позначкою «порада для всіх» (текст змінюється ключем `general_plain_label`).
- **Умовні кроки в «Що далі?».** Рядок у next_* можна почати з id теми: `[python] Записи курсу з Python уже є у бонусному блоці…`. Такий крок з'явиться лише тим, у кого ця тема «варто підтягнути» або «почніть з основ». Зручно, щоб не радити бонусний курс з Python тому, хто Python уже знає.
- **recap_title** — свій заголовок конспекту (наприклад, «Що вивчити до старту» для бекграунду). Порожньо — береться `recap_title` з settings.
- **course** — будь-яка назва курсу з вкладки courses вмикає в картці цієї теми підказку «Курс robot_dreams, який закриває: …». Квіз сам підбирає курс за прогалинами студента: радить лише курси, які закривають теми, що він не пройшов (за колонкою skills у courses), максимум два. Наприклад, при слабкому бекграунді, але Python на рівні, курс з Python не з'явиться, а курс з електроніки — так, якщо провалено «Сигнали та сенсори». Курс, вказаний тут, показується першим.
- **stage** — підпис етапу над питаннями цієї теми, наприклад «Знайомимося з вашим досвідом», «Трохи коду». Якщо порожньо — показується назва теми.
- **note** — додаткова підказка в картці прогалини. Пишіть сюди лише те, що справді отримують **усі** студенти (наприклад, підготовчі матеріали в LMS). Бонуси, які видають за запитом, не згадуйте — інакше квіз пообіцяє те, чого в студента немає.

## Вкладка `questions`

| id | skill | type | question | code | options | explanation | order | active |
|---|---|---|---|---|---|---|---|---|
| q3 | physics | check | Частота зросла з 200 до 400 Гц. Що змінилося? | | `2 \| Звук став вищим`<br>`0 \| Звук став гучнішим \| Гучність залежить від амплітуди`<br>… | Частота визначає висоту… | 3 | TRUE |

- **type**: `check` — перевірка знань: після відповіді студент бачить правильний варіант і пояснення. `self` — самооцінка досвіду, без «правильно/неправильно».
- **options**: кожен варіант з нового рядка (Alt+Enter у клітинці) у форматі `бали | текст | коментар`. Правильна відповідь у `check` — варіант з найбільшими балами. Третя частина (необов'язково): у `check` — коментар, чому цей варіант неправильний (студент бачить його, якщо обрав саме цей варіант); у `self` — короткий підпис під варіантом, щоб людині легше було впізнати себе («Пишу на Python регулярно» → «Це частина моєї роботи»).
- **Порядок варіантів.** У питаннях `check` варіанти перемішуються для кожного студента, тож правильну відповідь можна писати першою. Самооцінки (`self`) показуються в порядку з таблиці. Щоб змінити поведінку для окремого питання, додайте колонку `shuffle` зі значенням TRUE або FALSE.
- **Підтвердження відповіді.** Клік лише обирає варіант — його можна змінити. У питаннях `check` відповідь приймається після кнопки «Відповісти», тож випадковий клік нічого не зараховує.
- **Після відповіді** підсвічується лише обраний варіант. Якщо відповідь неправильна, студент бачить коментар до свого варіанта, правильну відповідь і пояснення.
- **code** — фрагмент коду, показується моноширинним блоком.
- **active** = FALSE ховає питання.
- У питаннях, варіантах і поясненнях працює Markdown (`**жирний**`, `` `код` ``).

## Матеріали: загальна база r_d + власні рядки курсу

Матеріали для прогалин збираються з двох джерел:

1. **Загальна база** — «База ресурсів r_d для вхідного квізу» (232 перевірені безкоштовні ресурси за всіма напрямами r_d, 40 статей r_d). Вона лежить у вкладці `base` — скопіюйте туди вкладку «Ресурси» з бази або підтягніть формулою `=IMPORTRANGE("посилання_на_базу"; "Ресурси!A:O")`, щоб усі квізи оновлювалися з однієї бази.
2. **Власні рядки курсу** — вкладка `resources`: те, чого в базі немає (нішеві теми курсу).

Як це працює:
- У вкладці `skills` у колонці **tags** перелічіть теги з бази через кому: `physics.school, physics.sim`. Можна весь напрям: `math.*`.
- Для кожної прогалини квіз показує до **resources_limit** матеріалів (у `settings`, за замовчуванням 5): спершу власні рядки курсу в порядку з таблиці, далі база — robot_dreams → українською → простіші.
- **resources_max_level** (за замовчуванням 1) — найвищий «Рівень» з бази для вхідного квізу: 0 — з нуля, 1 — база. Рівень 2 (поглиблення) не показується.
- Рядки бази зі статусом «Виключити» не показуються. Однакові посилання не дублюються.
- **base_verified_only** (TRUE за замовчуванням) — з бази беруться лише рядки з датою в «Статус перевірки». Так у квіз потрапляють тільки перевірені вручну конкретні сторінки, а не головні сторінки каталогів, цілі підручники чи тести.
- **Принцип добору:** лише конкретна сторінка під тему (стаття, розділ документації), яку ви відкрили й переглянули. Не даємо головні сторінки бібліотек, цілі підручники, тести на кшталт НМТ.

### Вкладка `resources` — власні матеріали курсу

| skill | title | url | source | format | time | lang | order | active |
|---|---|---|---|---|---|---|---|---|
| physics | Технологія звуку: … | https://robotdreams.cc/uk/blog/… | robot_dreams | стаття | 8 хв | UA | 1 | TRUE |

**Які джерела можна давати:** матеріали robot_dreams (блог, гайди, YouTube), DOU, Stack Overflow та офіційна документація інструментів (Python, NumPy, scikit-learn тощо). Не даємо: Вікіпедію, курси інших шкіл і платформ, сторінки конкурентів.

## Збереження результату

- **Після оновлення сторінки** студент одразу бачить свій останній результат з датою — квіз не треба проходити знову. Результат зберігається лише в браузері студента (localStorage), на сервер нічого не передається. Кнопка «Пройти ще раз» його стирає. Якщо в таблиці змінили питання, старий результат автоматично не показується.
- **«Зберегти результат у PDF»** відкриває системний діалог друку → «Зберегти як PDF». Для PDF є окремі стилі: світла тема, без кнопок, під кожним матеріалом — повне посилання.

## Статистика проходжень (необов'язково)

Квіз може анонімно надсилати результати у вашу Google-таблицю: скільки студентів пройшли, розподіл результатів і середні відсотки за темами по кожному потоку, найскладніші питання. Налаштування — 5 хвилин, інструкція в [scripts/apps-script/README.md](scripts/apps-script/README.md). Потік задається в посиланні: `…/?stream=2`. Поки `statsUrl` у `config.js` порожній, квіз нічого не надсилає.

## Як рахується результат

1. Для кожної теми: сума балів / максимум → %.
2. ≥ `threshold_ok` → «на рівні». Нижче `threshold_block` **і тема критична** → «почніть з основ». Інакше — «варто підтягнути».
3. Є хоча б одна «почніть з основ» → **закласти основи**. Інакше є хоча б одна «варто підтягнути» → **з підготовкою**. Інакше → **готові**.

Квіз нічого не зберігає і не збирає контактів — усе рахується в браузері.

## Брендові файли

- **Шрифт.** Vin Mono Pro — платний: покладіть `VinMonoPro-Bold.woff2` (з вебліцензією) у `assets/fonts/`. До того часу працює JetBrains Mono. Текст — IBM Plex Sans (Google Fonts).
- **3D-об'єкти** результатів — з бібліотеки шаблону r_d (`assets/img/`). Щоб замінити, покладіть файл з тією ж назвою.

## Якщо не працює

- **Сторінка показує копію, а не свіжі дані / Action падає з «HTML замість CSV».** Таблиця не відкрита за посиланням або корпоративний Google Workspace блокує доступ поза доменом. Перевірте посилання в режимі інкогніто. Варіант: «Файл → Поділитися → Опублікувати в інтернеті» → CSV для кожної вкладки → вставити в `config.js → csvUrls`.
- **Не видно питання.** Перевірте, що `skill` збігається з `id` у вкладці `skills`, у `options` щонайменше 2 рядки, а `active` не FALSE.
- **Розклад Action зупинився.** GitHub вимикає розклад у неактивних репозиторіях — запустіть вручну.
